# Claude Code Session Log Messages

**Last Updated**: 2025-12-10

---

## Overview

Session log messages represent the conversation history in Claude Code. They are stored in JSONL files and capture the complete interaction between users, assistants, and the system.

**Location**: `~/.claude/projects/-workspace/{session_id}.jsonl`

**Message Types**: `user`, `assistant`, `system`, `file-history-snapshot`, `summary`

**Common Fields**: Most messages include `type`, `uuid`, `timestamp`, `isSidechain`, `sessionId`, `cwd`, `parentUuid`, `userType`, `version`, and `gitBranch`. Exceptions: `file-history-snapshot` and `summary` types do not include most of these fields.

**Note**: Examples below are simplified, showing only essential fields. Actual messages contain additional metadata fields.

---

## Missing Examples

This document is missing examples for the following session log message variants. To find them in your own session logs:

**Failed tool results**: Tool result messages where `is_error: true`:
```bash
cat ~/.claude/projects/-{project_workspace}/{session_id}.jsonl | jq 'select(.message.content[]?.type == "tool_result" and .message.content[]?.is_error == true)'
```

**Mixed assistant messages**: Messages containing both text and tool_use blocks in the same content array:
```bash
cat ~/.claude/projects/-{project_workspace}/{session_id}.jsonl | jq 'select(.type == "assistant" and (.message.content | length > 1) and ([.message.content[].type] | contains(["text"]) and contains(["tool_use"])))'
```

**Other system message subtypes**: System messages with subtypes other than `stop_hook_summary`:
```bash
cat ~/.claude/projects/-{project_workspace}/*.jsonl | jq -r 'select(.type == "system") | .subtype' | sort -u
```

## Message Types

### User Prompt (Actual User Input)

```json
{
  "type": "user",
  "isSidechain": false,
  "message": {
    "role": "user",
    "content": "we modified document-reviewer agent. spawn it and have it review ARCHITECTURE.md"
  },
  "uuid": "877d773f-ee67-404c-8905-22a836b8a101",
  "timestamp": "2025-12-11T00:49:58.243Z",
  "sessionId": "338a2bf2-9a80-4ec6-8cc6-cac916b62270",
  "cwd": "/workspace"
}
```

**Note**: Actual user prompts have `isSidechain: false` and do NOT have an `isMeta` field.

---

### Meta User Message (System-Generated)

```json
{
  "type": "user",
  "isSidechain": false,
  "isMeta": true,
  "message": {
    "role": "user",
    "content": "Caveat: The messages below were generated by the user..."
  },
  "uuid": "5242eea7-0082-4902-abbe-89caafd68146",
  "timestamp": "2025-12-11T00:49:18.014Z",
  "sessionId": "338a2bf2-9a80-4ec6-8cc6-cac916b62270",
  "cwd": "/workspace"
}
```

**Note**: System-generated meta messages have `isMeta: true`. This field is absent from user-submitted messages.

### Sidechain Message (Agent Execution)

```json
{
  "type": "assistant",
  "isSidechain": true,
  "userType": "external",
  "message": {
    "role": "assistant",
    "model": "claude-sonnet-4-5-20250929",
    "content": [
      {"type": "text", "text": "I'll review the implementation of Task 4 against the plan requirements."}
    ]
  },
  "uuid": "58b37a93-75af-4e5c-bfd7-b96ad63ca24e",
  "timestamp": "2025-12-10T03:51:12.949Z",
  "sessionId": "862867f5-5738-4d23-beb7-7c2f6ba8e1ff",
  "cwd": "/workspace",
  "agentId": "040432c8",
  "slug": "scalable-kindling-dove"
}
```

**Note**: Sidechain messages appear in agent transcript files (`agent-{agentId}.jsonl`) and represent messages from spawned subagents. They include additional fields like `agentId` and `slug` for agent identification.

## Use Cases

Session log messages are used for:
- **Conversation history**: Complete record of user-agent interactions
- **Agent resume/continuation**: Restoring context for ongoing sessions
- **Debugging agent behavior**: Analyzing what the agent saw and did
- **Analyzing conversation flow**: Understanding decision-making patterns
- **Session state management**: Tracking current session state
